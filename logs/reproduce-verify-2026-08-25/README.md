# The shipped reproducer, run again after a week of module rebuilds, 2026-08-25

Generated by running [`reproduce.sh`](../../reproduce.sh) from a clean copy of the
repository on the board, which is what the front page tells a reader to do.
`verify.out` is the whole run and `state.txt` records the kernel, the boot
arguments and the module path it ran against.

## Why run it again

Two earlier verifications exist, on 19 and 22 August. This one was worth doing for
a reason those did not have: the intervening week put a dozen instrumented amdgpu
builds on this board and took them off again, chasing the reset defect, and the
last of those rebuilds was restored by hand. A reproducer that passed before that
churn is not evidence that it passes after it.

It also follows a pass in which trying to re-run a probe rather than read about it
found that the environment behind the PyTorch section no longer exists
([the note in the companion](../../INVESTIGATION.md)). That is the kind of thing
only execution finds, so the other shipped path deserved the same treatment.

## Result: every stage passes

    == versions ==
    kernel:  7.1.8-100.fc43.x86_64
    rocblas: rocblas-6.4.4-1.fc43.x86_64
    CUs:     40 (simd_count 80), the community unlock is active

    == 1. rocBLAS gfx1013 code objects ==
    == 2. rocBLAS SGEMM: system library, override, and native build ==
    ROCBLAS FAIL ... status=6 (rocblas_status_internal_error)   <- the system library, as designed
    ROCBLAS_PROBE_OK                                            <- the override
    ROCBLAS_PROBE_OK                                            <- the native build
    == 3. compute correctness: graphics queue (RustiCL, OpenCL) ==
    OPENCL_COMPUTE_OK
    == 4. compute correctness: MEC compute queue (HIP), small vs large ==
    RESULT: total_wrong=0 -> ALL CORRECT                        <- small kernel
    RESULT: total_wrong=0 -> ALL CORRECT                        <- large kernel

The `ROCBLAS FAIL` line is the point of stage 2 rather than a failure of it: the
system rocBLAS has no gfx1013 code objects and aborts, which is the defect the
native build exists to answer.

So the unlock survived the rebuilds, the native library is still the one being
loaded, and both compute queues still return correct results.
