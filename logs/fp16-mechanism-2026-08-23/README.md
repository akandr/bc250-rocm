# The fp16 mechanism, re-verified directly, 2026-08-23

Generated by `scripts/three_gaps.sh`, using the `BC250_TEMP` instrumentation
already in this tree, which sums the GEMM output before the f16 to f32
conversion writes it into the tensor.

## Why

This repository states the mechanism as "the first fp16 cuBLAS call of each graph
execution returns exactly zero, when the other 35 in the same pass do not". Every
recent measurement has been perplexity, which sits far downstream of that. The
claim had not been checked directly on the current stack, and a mechanism that
had quietly changed would invalidate the reasoning built on it.

## Result: confirmed, and sharpened

One perplexity chunk on the 8B with fp16 compute recorded 144 GEMM outputs.
Exactly three are zero, at positions 37, 73 and 109.

At 36 calls per graph execution, 144 outputs is four executions, and those three
positions are the first call of executions two, three and four. The first call of
the first execution is not zero: it reads 9361.13.

So the statement holds with one refinement worth making. It is not the first call
of every execution, it is the first call of every execution after the first.
The natural reading is that the first pass captures the graph and the later ones
replay it, and only replays are affected, though nothing here tests that directly.

The f32 control records no GEMM outputs through this path at all, which is
consistent: with the compute type forced to f32 the conversion path this probe
instruments is not taken.

## The other assertion, now tested

This page had said that the native rocBLAS cannot serve a gfx1010 override because it
carries only gfx1013 code objects. That was an assertion, not a measurement, and
assertions of that shape have been wrong here before. Tested:

    rocBLAS error: Cannot read .../rocblas/library/Te...

It fails, as claimed, and now with evidence. The consequence stands: the ISA and
the serving library cannot be separated on this board, because no combination
puts gfx1013 code under a non-gfx1013 override or the reverse.
