# The shipped reproducer, re-run on the current configuration, 2026-08-22

Generated by running [`reproduce.sh`](../../reproduce.sh) from a clean copy of
this repository on the board, with the fault hunt stopped so nothing else was
using the GPU.

## Why re-run it

The previous verification is from 19 August. Three things about the board have
changed since: the SDMA microcode was replaced with navi12's, the kernel moved to
7.1.8, and `amdgpu.gpu_recovery=0` was added. A reproducer that passed before
those changes says nothing about the configuration the README now recommends.

`state.txt` records what it ran against.

## Result: every stage passes

| stage | result |
|---|---|
| CU count | 40, the community unlock active |
| rocBLAS code objects | gfx1013 absent from the system library, as documented |
| SGEMM, system rocBLAS, no override | fails with `rocblas_status_internal_error`, as documented |
| SGEMM with `HSA_OVERRIDE_GFX_VERSION=10.1.0` | correct |
| SGEMM with the native gfx1013 build | correct |
| compute through the graphics queue (RustiCL) | correct |
| compute through the MEC queue, 1M threads | 0 wrong |
| compute through the MEC queue, 16M threads | 0 wrong |

Exit status 0.

So the recipe as written still produces a working stack on a board carrying all
of this year's changes, and the failure modes the reproducer asserts, the system
library aborting and gfx1013 being absent from it, are still true rather than
having quietly been fixed underneath.
