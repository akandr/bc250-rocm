Is the zeroed fp16 GEMM specific to the flash-attention path? No.

Flash attention was varied on 18 August already, in `loose-ends-2026-08-18/controls/`,
where four fp16 `-fa off` runs returned 14.09, 17.93, 15.33 and 14.88 and the
conclusion recorded there is the same one this run reaches. What that arm did not
have was an f32 control in the flash-attention-off cell, so it established that the
defect survives without establishing that the cell is otherwise correct. This run
completes the 2x2. Two rounds of all four cells, 8B at context 2048 over two chunks:

| flash attention | compute type | round 1 | round 2 |
|---|---|---|---|
| on | f32 | 9.0975 | 9.0975 |
| on | f16 | 14.8265 | 15.5604 |
| off | f32 | 9.1404 | 9.1404 |
| off | f16 | 15.1725 | 11.5830 |

The defect is present with flash attention off just as with it on, so it does not
belong to that path. The f32 controls are bit-identical within each setting, and
the small difference between the two f32 values (9.0975 against 9.1404) is the
two attention implementations differing slightly, not the defect.

Consistent with everything else known about it: the fp16 arms vary run to run
while the f32 arms do not, in both configurations.

That makes seven hypotheses eliminated: kernel selection, HIP graph capture,
instrumentation sensitivity, corrupt arguments, the destination pool buffer,
corpus dependence, and now the flash-attention path.
