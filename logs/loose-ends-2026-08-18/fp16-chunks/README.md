Perplexity at one, two and four chunks with fp16 compute, two runs each, plus an
f32 control at each length. Generated by `scripts/gap_probe_three.sh` (arm 1).

The arm was written to test whether forward-pass count governs the zeroed fp16
value projection, on the assumption that `--chunks` selects passes. It does not:
one chunk at a 2048-token context is already several forward passes, so the
clean single-pass arm the design called for was never present. The numbers still
show the error and the run-to-run spread both growing with the amount of text
evaluated, which is what they are cited for.

`harness.log` is the full run log, shared with the other two arms.
