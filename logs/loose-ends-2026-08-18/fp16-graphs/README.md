# Is HIP graph capture involved in the zeroed fp16 GEMM? 2026-08-18

Generated by `scripts/fp16_graph_arms.sh`.

Every previous observation of this defect came from a run with HIP graph
capture enabled, and the defect had never been tested with capture off. If it
disappeared there, it would belong to the capture-and-replay machinery rather
than to rocBLAS or the hardware, which would be the most useful thing left to
learn about it.

## Result: graph capture is not involved

Six perplexity runs per arm on the 8B, two chunks at context 2048:

| arm | values | distinct |
|---|---|---|
| fp16 compute, graphs on | 19.34, 17.83, 18.30, 20.25, 20.25, 18.30 | 4 |
| fp16 compute, graphs off | 20.25, 25.09, 21.32, 16.87, 15.28, 18.30 | 6 |
| f32 compute, graphs on | 9.0975 six times | 1 |

Disabling capture leaves the defect exactly as present. If anything the spread
is wider with it off, though six runs cannot separate that from chance. The f32
arm returns one identical value six times, which is both the correct result for
this configuration and a demonstration that the harness itself is stable.

## Two notes on reading this

The reference value for this configuration is 9.0975, not the 7.3503 quoted
elsewhere in the repository for the same model: that figure is an eight-chunk
gate and these are two-chunk runs. A first pass at this experiment classified
every arm as failing by comparing against the wrong one.

The fourth arm in the script uses qwen3-14B as a model whose value weights are
quantized, and it reads 15.39, 24.81 and 17.29 with fp16 compute. That is not a
counterexample to anything here: qwen3 dense models carry a separate known
corruption that the f32 compute type also fixes. The model that genuinely never
reaches this path is deepseek-r1-14B, whose value weights are q6_K, and this
run did not test it.

## What is left

The defect remains open and its scope is unchanged: it needs a running model,
it is not reproducible standalone or from PyTorch on the same rocBLAS, and
`GGML_CUDA_CUBLAS_COMPUTE_TYPE=f32` avoids it completely. What this removes is
the graph-capture hypothesis.
