Does the 16384-byte SDMA copy boundary move with `GPU_STAGING_BUFFER_SIZE`?

It does not. A 1 MiB host-to-device copy hangs unset and at 4, 64 and 1024,
while `GPU_FORCE_BLIT_COPY_SIZE=1024` completes the same copy in the same
session. So the boundary is set by which path ROCclr selects, not by how much
staging memory that path is given.

Generated by `scripts/gap_probe_three.sh` (arm 2). Only the summary lines were
captured; the probe binary's own output was not redirected to a file, which is a
harness omission rather than a missing result, since the outcome is binary
(completes or hangs) and is what the summary records.
