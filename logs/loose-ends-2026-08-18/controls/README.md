# Three controls, 2026-08-18

Generated by `scripts/loose_end_controls.sh`. Each closes something the first
round left as an inference or tested against the wrong subject.

## 1. The quantized-value control, run against the right model

The first attempt used qwen3-14B, which carries a separate known corruption and
therefore cannot test the claim. deepseek-r1-14B is the model whose value
weights are q6_K and which the top-level README says never reaches the affected
path.

    fp16 compute:  5.9756, 5.9756, 5.9756, 5.9756
    f32  compute:  5.9756, 5.9756

Six runs, one value, bit-identical, and the compute type makes no difference at
all. The claim holds.

## 2. The bandwidth explanation for the 8B decode variance, demonstrated

The variance measurement found the 8B decode rate varying by 15 percent at a
fixed depth and attributed it to running near the memory ceiling. That was an
inference from utilisation figures. If it is right, a model far from the ceiling
should be stable under the identical measurement.

| model | share of the 402 GiB/s ceiling | n | mean | sd | cv | spread |
|---|---|---|---|---|---|---|
| qwen2.5-1.5B Q4_K | 29 percent | 10 | 79.16 | 0.50 | 0.6 percent | 1.7 percent |
| qwen3-8B Q8_0 | 80 percent | 10 | 17.66 | 0.76 | 4.3 percent | 15.4 percent |

The coefficient of variation differs by a factor of 6.7 in the predicted
direction, on the same board, same depth, same measurement, same session. The
explanation is no longer an inference.

## 3. The fp16 defect with flash attention off

Graph capture had already been ruled out. Flash attention off changes the graph
shape entirely and is the other obvious structural difference.

    fp16, flash attention on:   19.34, 17.83, 18.30, 20.25, 20.25, 18.30
    fp16, flash attention off:  14.09, 17.93, 15.33, 14.88

Still wrong, still variable. So the defect does not depend on the flash
attention path either, and survives both structural changes tried.
