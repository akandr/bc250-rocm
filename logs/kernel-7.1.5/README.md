# First test on kernel 7.1.5, July 2026


Generated by `scripts/probe_kernel_sweep.sh`.

Built and booted 7.1.5 to see whether the defects were a regression that a
newer kernel had fixed. The answer recorded here was no, both the correctness
defect and the wedge still reproduced.

| file | what it is |
|---|---|
| `BUILD-RECIPE.md`, `amdgpu_build.log` | how the module was built for this kernel |
| `environment.log` | versions and boot arguments for the run |
| `compute_probe_fresh_samples.log`, `compute_probe_first_sweep.log` | the correctness probe on fresh boots and across sizes |
| `rocblas_sgemm.log` | native rocBLAS SGEMM on the same boot |
| `dmesg_faults.log` | the kernel side |

**Read the boot arguments before reading the conclusion.** This test carried
`amdgpu.sched_policy=2`, which was standard practice here at the time. That
setting is now known to be what makes sustained compute wedge, on this kernel
and on 6.18.9 alike, so the failures recorded here belong to the
software-scheduling path rather than to the kernel version. With hardware
scheduling the same workloads run clean on this kernel. The top-level README
sets this out under "A working configuration" and in the correction at the end
of Observation 2.
