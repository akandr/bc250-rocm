# Benchmark logs, fixed llama.cpp stack, 2026-08-12 and 2026-08-13


Generated by `scripts/bench_fixed_stack.sh`.

Two things to know before reading these.

**The `rc=` values in `campaign.log` are wrong and should be ignored.** The
harness that wrote them expanded a command substitution before `$?` in the same
string, so every line reports the exit status of the `date` call rather than of
the benchmark, which is always zero. Several runs recorded as `rc=0` in that
file in fact aborted. Every verdict in the write-up was taken from log
*content* instead (`Final estimate`, `backends passed`, `Memory access fault`),
which is why the mistake changed no conclusion. Judge these logs the same way.

**Provenance differs between the first campaign and the `recipe_*` files.** The
`a_*`, `b_*`, `c_*`, `d_*` (ROCm) and `f_*`, `g_*` (Vulkan) files are the first
campaign, which ran against the *system* rocBLAS with no `f32` compute type
set. The `ab_*` files are follow-up runs with the native gfx1013 rocBLAS. The
`recipe_*` files are the final re-measurement with every model under one
configuration (native rocBLAS, `GGML_CUDA_CUBLAS_COMPUTE_TYPE=f32`, prefill and
decode in a single invocation), and those are the numbers the README tables
quote. The earlier files are kept because they are what showed the system
library aborting on shapes it has no gfx1013 code object for.
